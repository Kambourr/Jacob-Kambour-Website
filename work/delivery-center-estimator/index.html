Delivery Center
Estimator

Project overview

A macOS desktop app that answers one question: what if Tesla opens a delivery center in ZIP code X? It estimates cost per delivery, the top three cost drivers, the customer catchment and a 10-year cash flow, using public data only.

See it read a ZIP ↘How it works ↘

Independent project using public data. Not affiliated with or endorsed by Tesla.

94402 · SAN MATEO, CA

Model estimates from public data, as shown in the app.

Project objective

Where should the next delivery center go, and would it pay for itself?

A delivery center sells nothing on its own. Cars are ordered online and the center hands them over, so the case for a site rests on how many customers it can reach, what it costs to run in that location, and how its value is measured.

The estimator turns that into a ZIP-level model. Type or click any US ZIP code and every input resolves automatically from bundled public data. Nothing has to be typed by hand.

    The app opens on a dark map of US ZIP boundaries. White dots are existing Tesla delivery centers, taken from Tesla’s public Find Us list. All 41,034 resolvable ZIP codes are precomputed, so a click reads a stored result.

  2. 02

    One ZIP and its catchment

    Selecting San Mateo 94402 shades its gravity catchment: the nearby ZIPs whose deliveries a new center would attract after sharing them with the existing centers (Huff model, distance decay β = 2, 60-mile cap).

  3. 03

    Cost per delivery

    $619 per delivery on an estimated 5,565 deliveries a year: the annual cost of running the site, with capex spread straight-line, divided by the catchment’s deliveries.

  4. 04

    Top three cost drivers

    Labor 55%, lease 22% and capex 13% of annual cost. Wages come from BLS OEWS, rent from cited broker market reports, and fit-out from the DoD area cost factor for the county.

  5. 05

    Two cash-flow views

    A 10-year DCF at a 13.6% default discount rate. Standalone values the site on Tesla’s posted delivery fee: NPV $10.75M, IRR 63.6%. Incremental counts only what Tesla would save versus expanding an existing center: NPV −$3.39M.

  6. 06

    Low, base and high

    Scenarios move volume, wage, rent, fee, discount rate and horizon together. Standalone NPV is −$1.40M in the low case, $10.75M in the base case and $44.73M in the high case.

How it works

Four deterministic steps, run for every ZIP before the app ships.

01

Resolve the ZIP

The ZIP maps to its county, metro area and ZIP tabulation area, which selects the local wage, rent, electricity rate, property tax and construction cost factor.

02

Build the catchment

A Huff gravity model allocates each nearby ZIP’s expected deliveries between the new site and existing Tesla delivery centers, using straight-line distance × 1.25 and a 60-mile cap.

03

Cost the site

Labor, lease, utilities, freight and fit-out for a 25,000-square-foot center give an annual cost, a cost per delivery and the top three cost drivers.

04

Value it

A 10-year DCF reports NPV, IRR, and simple and discounted payback in two views, then low, base and high scenarios and a one-driver-at-a-time NPV tornado.

Built to be checked

41,034

US ZIP codes precomputed in the nationwide build, with 0 errors.

  • Deterministic

    The same inputs produce identical JSON results across runs and across processes. A determinism test checks it.

  • Golden tests

    Frozen inputs and the shipped assumptions must reproduce stored expected outputs. The suite runs in CI with linting and type checks.

  • No AI in the runtime path

    Every figure is ordinary Python. A test fails if the calculation, map or precompute code imports a language-model client.

  • Offline desktop app

    Results and ZIP boundaries ship inside the app. Only basemap tiles are fetched online, and the map still draws without them.

Accuracy & limitations

These are model estimates from public data, not Tesla figures. No internal data is used, and the project is not affiliated with or endorsed by Tesla.

Distance is straight-line × 1.25 rather than drive-time routing, and every delivery center is treated as equally attractive. The center list is a 2024 archived snapshot checked against newer public data, so it is a lower bound on competing sites.

California demand comes from state ZEV sales; elsewhere a national total is allocated by ZIP. Sales are scaled by a handover factor of 1.10 in the base case (1.00 low, 1.30 high). The 1.10 and 1.30 are assumptions, because no public source counts used-vehicle handovers.

The incremental view depends on how capacity-constrained existing centers are, which is not public, so it is modelled as a range. The wage series is automotive service technicians, not a full delivery-role mix.

What the project demonstrates

Turning an open siting question into a ZIP-level model: demand from a gravity catchment, unit costs from public data, a 10-year DCF with two views of value, scenario ranges and a sensitivity tornado, packaged as an offline desktop app with tests that keep every number reproducible.
