( PURPOSE )

Project objective

Quarterly analysis connects forecasts, reported results, business drivers, and a clear explanation of what changed. Generating the explanation is only one part of that work. Checking it matters just as much.

This project separates the calculations from the prose: code handles the data, forecasts and variance bridges; the model drafts commentary from those computed figures; code then checks the figures it cites.

( HOW IT WORKS )

How it works

01

Source the facts

Public SEC filings and Tesla delivery releases feed a DuckDB database. Values retain their filing and reporting period.

02

Model the drivers

Driver-based historical forecasts and variance bridges connect the financial result to the assumptions behind it.

03

Draft the explanation

An AI model writes commentary from a computed fact sheet, rather than interpreting raw filings on its own.

04

Check before publishing

Code checks cited figures against the fact sheet. A failed draft gets one retry; unresolved discrepancies stay visibly flagged.

PROJECT TOOLS

Python · SQL · DuckDB · OpenAI · Static dashboard

( EVALUATION )

Accuracy & limitations

The published forecasts are historical backtests across 12 quarters. Each uses information available at the previous quarter’s filing date. They are not live forward predictions.

A figure can be faithfully quoted while the forecast itself is wrong. The dashboard makes that distinction visible: forecast misses are shown, and numerical verification checks whether the commentary matches the underlying data.

The models are deliberately simple and transparent. Public delivery counts are manually transcribed from releases, then validated. The dashboard documents these assumptions alongside the results.

( SUMMARY )

What the project demonstrates

The project combines financial forecasting, database queries, variance analysis, and AI-generated commentary. Source references and numerical checks let readers inspect the analysis and its assumptions.
